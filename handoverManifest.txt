TITAN PROTOCOL HANDOVER MANIFEST
================================================================================

This system has been transformed into a fully agnostic Plug-and-Play DMA Bridge. 
The underlying mechanism is built on Eclipse iceoryx for zero-copy Shared Memory 
but exposes binary standards that can be instantly consumed by any downstream 
adapter (Svelte WebSocket gateways, DuckDB ingestors, Python listeners).

================================================================================
1. BINARY SCHEMAS (Protobuf)
================================================================================
The absolute source of truth for the binary interface is located at:
`schemas/titan.proto`

Do NOT read raw struct mappings from MQL5 (`TitanProtocol.mqh`). By the time the 
data reaches you, the Rust DLL has validated the CRC, verified sequence gaps, and 
serialized the data strictly into the Protobuf specification.

================================================================================
3. SEQUENCE SYNC PROTOCOL
================================================================================
Network or IPC interruptions are handled via Sequence IDs embedded in every tick.
- If `sequence_id` matches the cache, this is a Ghost Tick and is intentionally 
  dropped by the Rust normalizer.
- If `sequence_id > last_sequence + 1`, a network gap has occurred. Downstream 
  consumers will see a `log_warn` emitted by Rust.
- UUID Generation: A `Session UUID` is spawned every time the MT5 EA boots. It 
  broadcasts with the `SymbolMetadata` heartbeat. If a downstream consumer detects 
  a *new* UUID, it must clear its state, as the MQL5 adapter has rebooted and stale 
  Virtual SL/TP configurations have been erased.

================================================================================
4. NORMALIZER RULES
================================================================================
Symbol resolution is deliberately deterministic utilizing a simple string hash 
within the hot path: `symbol_id_cache = HashString(Symbol())`. A dictionary 
sync happens via the `SymbolMetadata` heartbeat mapping string names to integer IDs.

CRC32 Validation: Every tick undergoes hardware-accelerated CRC32 validation via
the crc32fast crate to detect corrupt DMA transfers.

================================================================================
5. ERROR REGISTRY 
================================================================================
The system adheres to the *Loud Failure Mandate*. If the producer halts, read the 
stdout (or `titan_bridge.log`) for the specific `ERR_` code. Do not guess root 
causes. See `docs/wiki/error_reference.md` for mitigation strategies.

12. MQL5 EA COMPILATION FIXES
================================================================================
The MQL5 source files required significant modifications to compile under 
MetaTrader 5's MQL5 compiler. The following changes were made to achieve 
successful compilation:

12.1 FILES MODIFIED FOR MQL5 COMPATIBILITY
--------------------------------------------------------------------------------

A. TitanProtocol.mqh
   Location: ea/Include/TitanProtocol.mqh
   
   Issues Resolved:
   - ERROR: '#pragma pack' directive not supported in MQL5
     FIX: Removed all #pragma pack statements; rely on natural struct alignment
     Note: Lines 32-34 document that C ABI alignment is achieved through 
           natural alignment of struct members
   
   - ERROR: C++ style DoubleToLong function unavailable in MQL5
     FIX: Implemented manual byte extraction via casting (lines 124-127, 130-133)
     Code: long bid_bits = (long)tick.bid;
     
   - ERROR: Struct passing syntax differences
     FIX: All struct parameters passed by reference using MQL5 '&' syntax
     Example: void TickToBytes(BinaryTick &tick, uchar &bytes[])

B. IceoryxMemPool.mqh
   Location: ea/Include/IceoryxMemPool.mqh
   
   Issues Resolved:
   - ERROR: 'const' qualifier not permitted on value parameters in MQL5
     FIX: Removed const from all method parameter declarations
     
   - ERROR: Reference syntax incompatibility
     FIX: Updated to MQL5 reference syntax: BinaryTick &tick
     Note: DLL import declarations use MQL5 array reference syntax for structs

C. Diagnostics.mqh
   Location: ea/Include/Diagnostics.mqh
   
   Issues Resolved:
   - ERROR: const method qualifier not supported in MQL5 class methods
     FIX: Removed 'const' from all method declarations
     Example: string GetSessionUUID() instead of string GetSessionUUID() const

D. HighPerformanceBridgeEA.mq5
   Location: ea/HighPerformanceBridgeEA.mq5
   
   Issues Resolved:
   - ERROR: Include path resolution failures
     FIX: Standardized include paths to use angle bracket notation with 
          subdirectory prefix: <TitanBridge\Filename.mqh>
     Paths: #include <TitanBridge\IceoryxMemPool.mqh>
            #include <TitanBridge\ParallelEngine.mqh>
            #include <TitanBridge\Diagnostics.mqh>

Object.mqh

Purpose: MetaTrader 5 standard library base class required by MQL5 compiler

12.3 TECHNICAL SUMMARY
--------------------------------------------------------------------------------
The MQL5 compiler enforces stricter syntax rules compared to C++:

1. No #pragma pack support - struct alignment must be handled through 
   careful member ordering and natural boundaries
   
2. No const qualifiers on parameters or methods - all const declarations
   had to be removed to satisfy compiler requirements
   
3. Different reference syntax - MQL5 uses '&' for both array and struct
   references, with specific rules about array passing
   
4. Limited bit manipulation - DoubleToLong unavailable; manual byte-level
   extraction required for binary protocol compatibility

5. Include path requirements - MQL5 requires specific directory structure
   under MQL5/Include/ for custom libraries

12.4 COMPILATION VERIFICATION
--------------------------------------------------------------------------------
All MQL5 files now compile without errors in MetaTrader 5 Build 4510+.
The EA successfully initializes, publishes ticks via Iceoryx shared memory,
and maintains CRC32 compatibility with the Rust DLL.
